The experiment in one line

We plant decoy credentials (fake passwords that look real) next to real ones. If an agent uses one, the trap fires — we catch it. We then compare four ways of running the agents:

1. Baseline — agents work alone, no shared notes
2. Coalition — agents share notes through common memory
3. Rotation — decoys change every round
4. Containment — a "broker" issues real access; decoys are useless

Damage is a scored number from the sandbox — higher is worse. Sharing memory lets attacks spread to other agents (contagion). The broker blocks every misuse, so even when the trap catches an attacker, no damage happens.

Jargon, in plain words

Honeytoken / decoy
A fake credential planted on purpose. Anyone who uses it gets caught — it's a tripwire, not a real password.
Trap activation
An attacker actually using a decoy. ("Caught attackers" above.)
Harm
Scored damage in the sandbox — using a credential you weren't allowed to. Only affects fake state, nothing real.
Contagion
One attacker's knowledge of the traps spreading to other agents through shared memory.
Broker
The only legitimate way to get access; it hands out real credentials and blocks decoy use, so abuse is impossible.
False positive rate (FPR)
How often an honest agent gets mistaken for an attacker. Our ~0–2% beats the 25–53% of existing detection methods.
Confidence interval (CI)
The range the true number probably sits in. Narrow = trustworthy. Today most are wide because runs are few.
τ³-bench
A published set of realistic business chores (retail, airline, banking) we borrowed for the honest agents' tasks.
Everything here ran on fake credentials in a local sandbox — nothing real was touched. Budget so far ≈ a few GPU launches, well inside the 12–15 GPU-hour cap.
